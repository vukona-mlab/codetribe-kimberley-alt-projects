# Title: ReactTS Todo Application

## Objective
A simple project to get you reintroduced to React components, TypeScript, and logic.

## Requirements

### User Interface
1. Use the [provided UI](https://www.figma.com/design/ckRZ0T1pxuq7BmC20czkNh/Simple-ToDo-List-Design--Community-?node-id=0-1&p=f&t=AJPhAoiSnM2jScAu-0) or any design of your choice to create a ReactTS application that allows users to add, and manage their task list. Provide your chosen design as an image or images at the root of your project.

### Features
1. Task CRUD
   - Allow users to add new tasks with the following
      - Title
      - Description
      - Due date
   - Allow users to update a task
   - Allow users to view a task
   - Allow users to delete a task
   - Allow users to mass deletion of tasks
   - Allow users to mark a task as complete and incomplete.

### Sprints
1. Sprint 1: Identify and create a .ts file/s for your types and interfaces
2. Sprint 2: Use the UI design to implement the UI, HTML and CSS
3. Sprint 3: Add in your TypeScript logic to make the application functional
4. Sprint 4: Revisit your application, and break apart the components into smaller reusable components.
5. Sprint 5: Introduce navigation and routing to the application. If everything is on the same page, interact with the browsers address bar by reflecting what the user is doing on the app, or alternatively move everything to its own page.

### Branches
1. main - Holds the instruction.md. Waiting for PR.
2. dev - For the overall project changes before final submission, i.e. all branches are pushed to GitHub and then merged into the dev branch. This is the only branch for which you create a PR when done.
3. feat/ts-types -  For sprint 1
4. feat/app-layout - For Sprint 2
5. feat/task-management - For Sprint 3
6. refactor/component-splitting - For Sprint 4
7. feat/routing - For sprint 5

Do not use uppercases in your branches. Only create one PR with your merged edits on the dev branch, other branches are for your own use case and getting you used to branching.

## Deliverables
1. Typescript types and interfaces in their own files
2. TSX files with UI structure
3. CSS files with UI layout definition and styling (unless done inline)
4. Project documentation
